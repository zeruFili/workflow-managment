§ 1

System Overview

This document defines the complete relational database schema for the business management platform. The system supports five operational domains:

Marketing Finance CEO Administration Design Quantity Surveying

It models the full lifecycle of customer acquisition, payment tracking, task assignment, submission, and review across all departments.

§ 1.1

Database Technology Assumptions

  • Primary Database: PostgreSQL 15+
  • UUID generation: gen_random_uuid() (pgcrypto extension)
  • Array columns: Native PostgreSQL TEXT[] for file attachment URL arrays
  • Timezone: All timestamps stored as TIMESTAMPTZ (UTC), displayed in EAT/UTC+3
  • Character Encoding: UTF-8
§ 1.2

File Attachment Strategy

All file attachments are stored as arrays of strings. In this schema, this is implemented using the PostgreSQL TEXT[] (text array) column type. Each element in the array is a fully-qualified URL pointing to a file stored in an external object storage service (e.g., AWS S3, Azure Blob Storage, or Google Cloud Storage).

§ 3

Notification & Unread Activity Tracking

A notification system must be implemented to inform users whenever a task, submission, or review is created.

⬡ notification
Each notification record informs a specific user of an event triggered by another user. Tracks viewed status for badge counts and activity feeds.
Column NameData TypeKeyNullableConstraintsDescription
idUUIDPKNOPRIMARY KEY DEFAULT gen_random_uuid()Unique notification identifier
user_idUUIDFKNONOT NULL REFERENCES user(id)Recipient — user who should receive the notification
from_user_idUUIDFKNONOT NULL REFERENCES user(id)Actor — user who triggered the notification
resource_idUUIDNONOT NULLRelated resource ID (task, submission, review, etc.)
resource_typeVARCHAR(50)NONOT NULL'task_assigned' | 'submission' | 'review' | 'posted job' | 'apply' | 'paused' | 'rate'
parent_idUUIDNONOT NULLAlways the ROOT task/card id
parent_typeVARCHAR(50)YESNULL'data_collector_task' | 'designer_task' | 'quantity_surveyor_task' | 'marketing_task'
typeVARCHAR(255)NONOT NULLHuman-readable label for the notification category
viewedBOOLEANNONOT NULL DEFAULT FALSEIndicates whether the notification has been viewed
created_atTIMESTAMPTZNONOT NULL DEFAULT NOW()Date and time the notification was created
Indexes
CREATE INDEX idx_notif_user_parent ON notification(user_id, parent_id, viewed); CREATE INDEX idx_notif_user_resource ON notification(user_id, resource_id, viewed); CREATE INDEX idx_notif_user_resource_type ON notification(user_id, resource_type, viewed); CREATE INDEX idx_notif_user_parent_type ON notification(user_id, parent_type, viewed);
Full DDL — notification table
CREATE TABLE notification ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), user_id UUID NOT NULL REFERENCES "user"(id), -- recipient from_user_id UUID NOT NULL REFERENCES "user"(id), -- actor (who triggered it) resource_id UUID NOT NULL, -- submission_id, review_id, task_id resource_type VARCHAR(50) NOT NULL, -- 'task_assigned'|'submission'|'review'|'posted job'|'apply'|'paused'|'rate' parent_id UUID NOT NULL, -- always the ROOT task/card id parent_type VARCHAR(50) NULL, -- 'data_collector_task'|'designer_task'|'quantity_surveyor_task'|'marketing_task' type VARCHAR(255) NOT NULL, -- human-readable label viewed BOOLEAN NOT NULL DEFAULT FALSE, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() );
